# v29 GPU pilot preparation, not model-quality results

The v28 prompt-only experiment did not earn a production change. This handoff prepares two small, controlled updates from the verified formal v0.2.2 adapter to test fixed-position paraphrasing while retaining natural translation. No v29 optimizer step or model generation has run during preparation. Production `src/` and the formal Q5_K_M model are unchanged.

The [full protocol](../../../training/mt-fixed-slots/PARAPHRASE_V29.md) fixes two final 32-step candidates (64 total), identical source/target order, LR `5e-6`, rank 32, alpha 64 and zero dropout. Only the fixed-task prompt differs: existing production versus archived v28 compact `scope-map`. This compares two complete prompt policies, not an isolated code-map change. Both start from adapter-file SHA `28a0bd981feab75390ec045a9b97b02401e8a5ab973118d7e54da7b9e77cf859`; the initial trainable-tensor digest is separately recorded and must match across candidates. The baseline is generated first; no checkpoint is selected by loss.

## Data and frozen evaluation

- 128 train / 32 validation / 32 synthetic holdout sources, eight relation categories and 32 split-disjoint syntactic families. Each candidate has 256 train and 64 validation rows, balanced fixed/natural tasks.
- All fixed targets pass the unchanged production decoder. Sources, delexicalized wires and prompts are unique; 1,195 previous project sources and 1,193 encodable wires are excluded. Exported source/reference identities are retained. Automatic frame validity does not prove semantic equivalence.
- References are assistant-authored and audited, not independently human reviewed. The audit corrected return/obtain wording, an indication versus guaranteed conditional, an omitted authored return verb, and if/when versus only-if before any v29 model output.
- Six new paragraphs, two each from MDN Promise/then, Python asyncio synchronization and Rust Result, were selected in Firefox before new model output. Capture succeeded on all three sites. [Source-only fixture](../external/paraphrase-web-v29.json) records attribution, capture hashes and the subsequent static nonce amendment; no web target enters training.
- The BF16 plan has 84 sources and 168 requests per model: synthetic holdout 96, new web 12, consumed v28 regression 28, consumed FLORES regression 32. Three models give at most 504 generation calls. References and production grammar are excluded from model inputs. Consumed regression sources are not presented as fresh holdout data.

The original main-PC source inventory was collected successfully: 24 files, 6,429 recognized canonical and delexicalized sources, hash-only inventory SHA `65662f1be53a370e55fab5c86605c164ae2e3ceb85a60fcc71f0f8eea28430a7`. The share then failed with `UNKNOWN realpath/stat/open`; a TCP probe from the MCP computer to `192.168.50.72:445` timed out. The complete private-source comparison was not finished remotely. A mandatory GPU-host stage now verifies the pinned inventory and every original file SHA, then compares all 198 new source fingerprints before loading any model. Missing files, changed hashes or collisions stop execution and retain failure status. This is a runtime gate, not a claimed successful private-data comparison, and exact recognized-format exclusions do not prove absence of semantic or pretraining overlap.

Keep `PageLingo-MT.cmd` as the environment entry and use only `x.cmd` for the task. The new prefix is `paraphrase-v29`, distinct from the completed scope-choice run. Main-PC work is GPU training and unconstrained BF16 evaluation only. No Firefox, CPU conversion, installation or upload is run there, and caches/temp/output stay on its project drive. The original formal adapter, base and previous outputs are preserved. The evidence ZIP contains no weights; adapters remain in the run directory for later conversion.

At source preparation time, share delivery is blocked by the observed SMB timeout and is not marked installed. This report is deliberately independent of the later package/delivery receipt. No training is started through MCP. After actual GPU results return, Cloud must review meanings and run quantized native plus actual Firefox/wllama comparisons. A release needs at least two complete repairs on the frozen new real paragraphs, no new critical semantic or code/link/emphasis ownership regression, exact DOM restoration, and median first-output latency no more than 1.5 times formal baseline. No automatic winner or production activation is included.
