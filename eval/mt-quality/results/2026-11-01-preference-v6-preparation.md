# 原始语料审计与 v6 语义偏好对照准备

2026-11-01。v5 候选仍不批准发布；本记录是数据审计和下一轮流程验证，不是新模型质量报告。

## 主力机实际审计

经授权共享目录读取了原始 train/validation/holdout/realweb JSONL 的行数、标记骨架、文字位置、保护项位置、源句去重和家族分布；原始 final/final-v3 保留作评测，不训练、不改文件。聚合统计见同目录 `2026-11-01-original-corpus-audit.json`，未发布原始私有句子或凭证。

原始 v0.2 训练 1,200 条、v0.2.1 修复 320 条、v0.2.2 微修复 80 条、v0.3 产品数据 192 条，均使用较早的可移动行内标记协议：全部记录均有文字位于编号标记外，部分保护项位于标记内，部分目标会移动标记骨架。现行固定槽要求每个原始 Text 节点独立编号、所有译文在对应编号内、保护项固定在编号之间，因此不能直接混入。

原始 holdout/smoke-v1.1 的 240 条源句中，26 条与某个原始训练文件的 model-visible source 完全相同。此审计只比较精确 wire source，不声称覆盖近似重复或所有语义泄漏。该目录不能整体当作独立测试证据。其余所审计 holdout 的精确 wire 重叠为零，也不等于自动证明盲测独立性。

`data/realweb/openclaw-real-v1.jsonl` 有 30 条含来源 URL 的双语记录，但仍是旧标记协议，且记录本身不是原始网站 DOM。没有将其视为本轮真实 Firefox 网站测试，也没有声称其中文参考已独立人工审核。

旧 r16 的训练结果明确记录 `fresh_base`，底座为 `tencent/Hy-MT2-1.8B`，实际固定槽输入为 480 条训练、64 条验证。它不是从原 v0.2.2 adapter 续训而来。因此不能把 v5 的问题未经验证归因于早期旧协议语料；原始数据发现只影响本轮能否复用。

## 本轮预先固定的比较

两组都恢复同一个旧 r16，使用生产 legacy 提示、相同正确译文与旧训练回放。对照只用 chosen CE，实验组增加冻结旧 r16 参考下的 DPO 语义偏好项；各 48 optimizer steps。完整目标函数、参考精度、哈希链与限制见 `training/mt-fixed-slots/PREFERENCE_V6.md`。

新增原句 96 训练、16 验证、16 留出。每对正负译文使用相同编号和保护项骨架，覆盖时间关系、否定和条件、参与者与已绑定方法、工具和对象及动作遗漏。新增数据由助手编写并检查，无独立人工审核；不同主题共享句式，不能声称跨句式泛化。

从精确匹配的旧训练集取 96 条回放，加上 96 条新训练对；32 条验证由 16 条新验证和 16 条旧验证回放构成，旧验证不参与优化。新增源句与既有训练/评测、移除代码身份后的 wire 输入去重；既有失败集继续只作诊断。已有 final 数据不进入这轮。

## 已实际完成的验证

- 两个目标各 128 条，合计 **256 次参考输出的生产 Node/DOM 回放**：正负译文全部能显示，原节点、属性、代码及精确恢复检查通过。它验证“错义负例也会通过结构检查”，不是模型生成或 Firefox 推理。
- `npm run verify` 通过，包含 **258 项 JavaScript 测试**、TypeScript、全部数据导出、构建和 addon lint。生产依赖审计 0 漏洞；addon lint 有 1 条既有 innerHTML 静态扫描警告，0 errors。
- 完整 ML 环境 **67 项 Python 测试全部通过**；轻量环境同一组测试通过，15 项可选 ML 测试跳过。
- 用随机初始化的极小 Llama+LoRA 实际执行自定义 Trainer 的 2 个 optimizer steps、梯度累计 2，确认仅 LoRA 更新、底座不变、损失有限；另外核对 causal shift、prompt/padding 梯度屏蔽、偏好项方向、对照及回放不惩罚负目标、固定参考与数据/分词/初始张量摘要校验。这不是 Hy-MT 质量或性能测量。
- 实际 Hy-MT 原 tokenizer 的两组 check 流程通过：训练 192 条（96 对比 + 96 回放），最多 **696 token**；验证 32 条，最多 **444 token**。两个目标合计 token 数分别为训练 **19,544**、验证 **3,620**，含回放重复的第二路前向。prompt/padding 屏蔽、EOS 监督、无截断。check 只读取权重文件核对 SHA，不加载 Hy-MT 权重或执行优化。
- 四组 BF16 评测预检通过：128 个非训练源句、每组 178 个固定请求，最多 **712 次计划生成**；当前尚未运行。沿用 v5 的 96 个源句和 25 组自然/角色诊断，再加入 32 个新非训练源句。无参考引导生成、无 grammar、无草稿改写。
- 完整工作流的模拟执行覆盖预检、冻结参考、两组训练、四组结果打包和初始张量不匹配中断，失败路径保留首个候选和 traceback。模拟结果不作为 GPU 训练证据。

主力机两个 CMD 入口的 SHA 已核对保持原样。新任务仍由原 `PageLingo-MT.cmd` 环境内执行 `x.cmd`，不需要 Firefox、CPU 转换、额外训练依赖或新底座下载；缓存与结果留在项目盘。
