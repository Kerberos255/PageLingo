# v8 实测：优先修固定槽任务与量化质量，暂不重训底座

2026-11-05。**本轮不支持“Hy-MT2-1.8B 基模已经不行”的判断，也没有证据支持继续照旧加训练轮数。** 同一句的自然翻译通常正确，固定槽输出却会反序、错配条件或改变强调范围；旧 r16 BF16 仍有反序，Q5 又额外触发了一个 nonce 误译。换用未经本项目适配的 Qwen3-4B 也没有成为可靠的固定槽替代品。

本轮实际完成 **115 次原生 CPU 生成，115/115 EOS；65 次生产 decoder/renderer 的 Node/DOM 回放，再做 65 次 Firefox 回放**。没有新训练、模型转换、上传权重、切换默认模型或改动主力机 CMD。生产扩展源码未改；新增评价工具、公开网页摘录、参考反馈与测量记录。

[逐例机器记录](2026-11-05-source-format-v8.json)保存实际输出、逐例理由、身份与测量；[复现说明](../SOURCE_FORMAT_DIAGNOSTIC_V8.md)说明提示差异和计数边界。语义为**助手逐例审查，未经独立人工盲审**，不能当作普遍翻译准确率或发布认证。

## 新网页与判断方法

从 Python `asyncio.Queue` / `sqlite3` 与 MDN `AbortController.abort` / `Promise.all` 的中英文页面实际取得快照，选取 **12 段原始英文 HTML**。题材覆盖任务计数、条件析取、事务提交/回滚、关闭前提交、否定、操作完成之前中止、任一拒绝与所有完成。源页/中文页 URL、抓取时间、整页及段落 SHA 保留在[摘录文件](../external/source-format-v8.json)。

中文页面只作整句意思参考，不拆成英文槽数、不输入模型、不要求逐字相同。例如公开中文的“关闭上下文管理器”有歧义，Qwen 固定槽写成“关闭连接的上下文管理器”更清楚，本轮判为忠实表达。真实源页和中文页均保留归属/许可来源。

另选 4 条原有训练源控制题：发送后加密、记录后校准、加密后发送、nonce 定义。它们与新网页分开统计，不算新泛化成绩。新网页按规范化原文及隐藏代码名后的输入检查与现有项目语料重复；“新”不代表底座预训练没见过公开文档。此组网页此后属于诊断/回归资料，不应自动转成训练输入。

每个 Q5 模型实际 37 次生成：16 条自然翻译、16 条生产固定槽、5 条事前选定的上下文研究提示。自然翻译能看到实际代码；生产请求看到 opaque token。5 条研究提示还改变了改写指令与角色上下文，不能把差异都归因于 grammar 或代码可见性某一个因素。

## 4 条旧训练控制题暴露任务差异

三个 Q5 模型的自然翻译均 **4/4 保留关键原意**。生产固定槽则为：

| 模型 | 忠实 | 轻微问题 | 明确错义 | 另记强调范围错误 |
| --- | ---: | ---: | ---: | ---: |
| 底座 Q5 | 2 | 0 | 2 | 3 |
| 旧 r16 Q5 | 1 | 0 | 3 | 1 |
| Qwen3-4B Q5 | 2 | 2 | 0 | 3 |

`Use encrypt_snapshot() to encrypt the snapshot after sending it to the mirror.` 的旧 r16 自然输出为“使用 encrypt_snapshot() 在将快照发送给镜像后对其进行加密”，固定槽却为“使用 encrypt_snapshot() 对快照进行加密，随后将其发送给镜像”，明确反序。`Calibrate the sensor after recording the next sample.` 同样自然正确，固定槽变成“校准传感器后记录下一个样本”。

Qwen 修正了这条加密顺序及 nonce 定义，但其他控制题仍有句法残缺、重复短语与强调范围扩大。因此没有据此直接替换底座。旧 r16 的四条生产请求 SHA、输出文字和结束状态均与 v7 完全一致。

5 条上下文研究提示没有成为可靠修复：旧 r16 关闭前提交一句更清楚，但两条时序反转未修复；Qwen 的事务条件仍混乱，abort 一条研究输出反而被目标语言校验拒绝。未接入生产默认提示。

## BF16 与参考似然补测

使用同一旧 r16 的 BF16 GGUF，对两条旧题各测自然/固定，共 **4 次生成、4/4 EOS**。与 Q5 的请求、实际 prompt、输入 token SHA 全部相同；既有转换记录确认该 BF16 文件就是旧 Q5 的量化输入。

- “记录后校准”在 BF16 自然翻译正确，固定槽仍成“校准传感器之后记录下一个样本”：时序错误不能只怪 Q5。
- nonce 在 BF16 自然/固定均正确；Q5 固定槽把 nonce 多次译成非对称密钥并自相矛盾：量化版本会影响个别错误，不能只测 BF16 就宣布部署质量合格。

再使用**原始 HF BF16 权重 + 同一旧 r16 adapter**，对 nonce 的三个完整目标做无梯度、无 grammar、无截断的 teacher-forced 计分，内容均值排除标记/EOS：

| 目标 | 整序列 log probability | 内容平均 log probability | 含 EOS 目标 token |
| --- | ---: | ---: | ---: |
| v7 旧固定参考 | -32.498802 | -1.229131 | 82 |
| Q5 实际错误输出 | -12.066941 | -0.372511 | 88 |
| BF16 实际正确输出 | -24.149490 | -0.877719 | 83 |

正确新表达比旧参考提高 **8.349313 nat**，但错误仍比新正确表达高 **12.082548 nat**，内容均值也更高。旧两项目标复算与 v7 缓存最大差 **0.0**。所以参考生硬放大了差距，错误偏好仍真实存在；原生 BF16 的局部贪心输出正确也不等于其正确整序列具有全局最高概率。此为一条旧训练源的事后诊断，未批准任何优化输入。

## 结构与实际性能

**65/65 Node 回放、65/65 Firefox 158.0.1 回放**保留原节点/子节点身份、属性、code 和精确恢复；Firefox 序列化源、文字及显示状态也均与 Node 回放一致。**63/65 显示译文，2/65 校验失败保留原文**。强调范围错误仍存在，说明原 DOM 不动不等于译义范围没变。这里是实际原生输出的浏览器回放，**不是新的 Firefox/wllama 推理或完整实时网站压力测试**。

以下是每个 Q5 模型 16 条生产固定槽的实际观测；server ready 已受权重 SHA 扫描暖缓存影响，不是冷盘加载。首片段指首个非空流式文本，并非逐 token 可见延迟。运行中有辅助资料/测试读取，数据是当前共享云环境观测值，未声称专用空载基准；不同 tokenizer 的 token/s 也不直接等同网页吞吐。
