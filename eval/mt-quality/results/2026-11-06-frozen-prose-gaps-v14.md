# PageLingo 原节点分配 v14 与 GPU 训练准备

同一批冻结自然译文在真实网页上，研究审查后显示数从 v12 的 **20 增至 24**，此前 20 条的完整译文保持相同。新增四条分别是 Kubernetes 容器链接、React 整句加粗及三条链接、Stack Overflow 的 jQuery/HTML 链接，以及 Python logging 的多代码/链接段落。**实验路径仍默认关闭，不能视为自动语义校验已完成。**

本轮已推进到需要 GPU 候选训练的节点：纯提示闭集范围选择基本不会做，异常来源误译在基础模型中也存在。已准备新的 128 步 fresh-base LoRA 试验，尚未执行任何 GPU 训练；主力机只负责 GPU 和 BF16，量化与 Firefox 留在云端。

## 合同改动与对照

先单独试验 v13：normal/nowrap CSS 下，ASCII 可折叠空白可规范化或保留为空。空白节点不能承载词语；NBSP、保留换行 CSS、代码和显式不翻译继续保护。该对照增加候选，却仍因缺少普通文字承载位置而被编译器拒绝：旧组机械可编译仍 21 条，新页组仍 2 条。v13 的 Wikipedia 一个源请求变化，35 个源/模型可复用；没有重生成旧译文或掩盖来源变化。

v14 显式给原普通文字及其间有限标点/空白增加程序写权限，允许同父节点内完整中文间隙落在原 Text 节点上，其他原节点可以为空。原代码、链接、元素、属性、顺序和每个格式范围保持；不能跨父节点、BR 或省略边界移动词语，也不能拼接受保护原子。此权限区别于原模型槽，详细合同见 [FROZEN_PROSE_GAPS_V14.md](../FROZEN_PROSE_GAPS_V14.md)。

独立 renderer API 用私有授权及完整冻结目标见证，校验 HTML 解析后的实际文本，再在应用前复核。模型 JSON 不能凭一个标记取得清空文字权限；CSS/源变化、CR 解析变化、代码修改均拒绝。整句格式还必须包含紧邻的同类终结标点，排除缩写，不能吞入其他词。初版 v14 曾把 React 加粗句号留在包装器外；初版源码、预览和失败均保留，最终版加入通用标点规则并重新采集/投影/预览。

沿用 v12 的 12 个旧页面和 3 个新增页面，复用正式 v0.2.2、旧 r16 的 72 条旧自然译文，以及正式模型的 13 条新页面/补充译文；本轮没有为这些网页重新生成译文。

旧组两个 API 声明继续不进入候选。r16 的一条 Wikipedia 记录在预览/写入时源合同变化；10 条新页中的一条 Docker 记录在写入时定位器/URL 变化。各阶段人数不是所有候选进入同一阶段的准确率，来源变化单独记录。全部之前成功显示的样本仍显示；增加的四条均使用原有冻结输出。

24 条旧组机械预览，范围审查 22 确认/2 错误；整句意义 16 忠实/5 次要问题/3 实质错误。两模型的 `dereferencing → 引用` 丢失完整“去引用”概念；两份 asyncio 异常返回译文改变抛异常的主体，因此拒绝。正式 Rust 还混入韩文及“去引号”误译，与范围错误重叠。最终拒绝四份不同候选，显示 20 份。五份次要问题包括术语及情态强度，继续标明，不包装成完全正确。

审查是助手检查绑定目标 SHA 的既有意义记录并复核本轮全部范围；新 logging 段落另行核对。不是独立人工盲审。范围分数和结构编译成功均不自动证明语义正确。

## Firefox 实际写入

Firefox 158.0.1、真实网页 CSS/脚本、TLS 验证开启、`acceptInsecureCerts=false`。85 条结果为 **24 显示、50 候选/对齐拒绝、5 编译拒绝、4 研究审查拒绝、1 源合同变化、1 定位器变化**。

24 条显示的八项检查全部 24/24：完整 owned 译文、原节点/树/属性/顺序、祖先结构、非 owned 文本、代码、链接属性及 onclick 身份、自定义非导航监听器、精确还原。60 条可定位拒绝均验证原文未动；一条缺失 Docker 来源无法实测其帧，记为未测。补充 Docker 段落本轮可定位但覆盖不足而拒绝，未重跑直到成功。

另回放原默认固定槽的 10 条记录，8 条来源匹配并显示，七项结构/监听器/还原检查全部通过；Docker 另外两条来源不匹配，不写入、记为未测。该对照仅验证默认 renderer 回归，不声称这八份固定槽输出整句质量合格。

这是原生模型输出在真实网页原节点上的回放，不是本轮 Firefox/wllama 或 WebGPU 模型推理，不代表完整扩展生命周期、全部站点监听器、像素布局或整站覆盖率测试。

## 换编码器及纯提示能否解决

另测试公开 `aneuraz/awesome-align-with-co`，revision `777756717e1fa9556e304d4d5db173ee386b9c16`。模型卡将它归于 neulab AWESOME with-co；这是第三方上传，未独立确认与作者原始分发权重逐字一致。

权重 1,086,292,375 B，SHA `9f9d19adbab07c9f5ec2d74fe5701a66c123919feb35d05fce29969b6a85adb9`。经验证代理下载到匿名 Linux memfd，没有落盘保存权重。第一次因 legacy torch 序列化不支持 mmap 失败；保留日志后，用 weights-only CPU 加载成功。最终下载 **162.433996 s**，加载 **3.527406 s**。取前 8 层；加载后进程 VmHWM **1,392,696 KiB**、RSS **941,108 KiB**，这些不是包含 memfd 在内的系统总内存峰值。

在 v13 固定的 48 对输入上，0.55 cosine mutual 得到 37 投影/11 拒绝；作者式双向 subword softmax 均超过 1e-3、映射到原 lexical words 后为 38/10。两种方法仍将两份 dereferencing 映射到不完整“引用”，四次 level 的补充段落仍覆盖不足。编码中位数 **0.188799 s/对**。这只是投影诊断，未将该编码器结果做真实浏览器写入，也未切换依赖。加载时出现通用 Mistral regex 警告，但实际是 BertTokenizer/BertNormalizer/BertPreTokenizer，词表 SHA 及四组 probe token IDs 与基线一致；未套用无关 regex 修复。

随后新增 **52 次原生 CPU 生成**：基础模型与正式 v0.2.2 各 18 条闭集选择、8 条自然翻译，全部 EOS。8 个可表示的概念各做两种字母排列，另有一个无连续完整范围的案例。

| 冻结译文范围选择 | 基础模型 | 正式 v0.2.2 |
| --- | ---: | ---: |
| 选择正确 | 2/18 | 3/18 |
| 有合法完整范围的选择正确 | 0/16 | 1/16 |
| 应放弃案例正确 | 2/2 | 2/2 |
| 两种排列均正确的有效概念 | 0/8 | 0/8 |

大多输出 X；输出格式由 grammar 限制，格式合规不等于选择正确。唯一选对 dereferencing 的正式输出在换排列后也放弃。

4 个自然翻译意义对照各用两种提示。基础与正式模型都在两种提示下把 Future 因抛异常完成译成函数通过抛异常返回；反向主体对照、回调完成后释放缓冲区、失败不能报成功，其余每模型 6 次均保持意义。这是小诊断集，说明问题并非全由框架引起，不能据此断言基模整体不行。

## 性能与环境

Debian 13.6、Linux 6.18.57、AMD EPYC 9V74，3 个可见 CPU，cgroup 配额 2 CPU、内存上限 8,589,934,592 B；本次记录 OOM/OOM kill 均 0。10:34 UTC 磁盘可用 **78,430,208 B**，因此不再落盘下载大型对照权重。会话级 cgroup memory.peak 为 6,380,650,496 B，不能归因到某一个模型进程。
