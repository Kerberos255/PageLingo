# PageLingo 真实网页结构回填 v11（2026-11-06）

本轮完成生产序列化器的可选文本归属追踪，并在 Firefox 158.0.1 上重新访问 12 个真实网站验证。**36 个非 API 样本均能建立与生产请求一致的归属模型，上轮为 28 个；10 份经范围审查的译文实际写入并通过全部结构检查。实验回填仍不适合默认开启。**

原因分两类：独立标点/空白节点属于生产流程的只读内容，常见的中文标点转换因此会被严格合同拒绝；词对齐仍有把完整概念映射到部分词义的错误。前者需要调整框架合同，后者需要改善范围预测。此轮结果不能证明继续微调 PageLingo-MT 可以解决它们。

本轮属于 **v10 已见样本的回归实验**：复用 v0.2.2 Q5_K_M 和旧 r16 Q5_K_M 的 72 份自然译文，新增翻译生成 0、训练 0。没有重新评定整段翻译质量；范围审查不等于整段语义正确。原 v10 翻译质量、原生加载时间、TTFT 和生成速度见[上一轮报告](2026-11-05-complex-live-web-v10.md)。

## 实现与合同

生产改动仅为 `serializeRichSegment(..., {fixedTextSlots: true, captureOwnership: true})` 提供可选追踪。追踪复用原遍历，记录真正可写的 Text 槽、原始代码/只读文本、隐藏内容、独立子根、BR/WBR、块容器、链接回退和传输裁剪，不再用整棵 `root.textContent` 代替请求输入。36/36 样本的自然请求、现有固定槽请求及开启/关闭追踪的传输内容均一致。

实验编译器只向原有生产槽分配完整冻结译文。格式与块边界需要明确范围，只有覆盖完整父范围的 flow 可以继承父范围。代码和只读标点必须逐字保留，不能新增节点、移动节点、改写目标文字或人为修改对齐范围。网站修改 owned 文本、代码、标点、属性、树或 CSS 归属后，旧结果失效；独立子根和隐藏文本的后续文字变化可以保留。

预览只编译、不写原 DOM。实际写入还需绑定原文合同、完整译文和精确范围的离线审查。本轮审查者为 assistant，没有独立人工审核；这是研究记录，不是产品用户审批流程，也不是自动语义校验。详见[完整合同](../OWNED_PROJECTION_V11.md)。默认翻译路径、默认模型和权重均未切换。

## 语义范围错误仍存在

15 份机械可编译提议中，2 份仍把 `<em>dereferencing</em>` 映射到“引用”，把“去”留在强调范围外。整句文字是否流畅与该格式范围是否完整，是不同问题。两份均判为错误并在原 DOM 写入前拒绝。

另有 3 份 `Note:/Warning:` 的强调范围只包含“注意/警告”，没有包含冒号。按完整原格式范围的合同保守判为存疑，全部拒绝。没有手动扩展范围以制造通过。

**最终 10 份显示结果只有旧 r16 的 `Repeated crashes → 重复崩溃` 含可变语义格式范围；其他样本主要验证只读锚点或完整父 flow。** 因而不能用 10/10 的结构通过数宣称复杂语义对齐已自动解决，也不能将其与 v10 的未经此审查筛选的显示数直接比较为质量提升。

## Firefox 实际写入检查

两个模型各 36 条，共 72 条 commit 回放。实际状态为：10 条审查后显示、53 条候选/投影拒绝、3 条编译拒绝、5 条范围审查拒绝，以及 1 条旧 r16 的 Wikipedia TLS 2 因实时原文合同变化拒绝。合同检查先执行，因此该条取代了预览阶段的一条候选/投影拒绝；它不是模型错误。工具没有保存该次合同变化的具体字段，不对变化原因作推断。

10 次写入的下列检查均为 **10/10**：完整 owned 目标文字一致、原节点/树/顺序/属性不变、祖先结构不变、非 owned 文本不变、代码不变、链接属性及 onclick 对象不变、同一链接对象上的自定义非导航监听器仍工作、还原后原 HTML 完全一致。其余 **62/62** 条在拒绝后原文未改动。

实际显示分布：Kubernetes 1、GitHub Docs 3、MDN 2、Python 2、W3C 2。12 个站点无脚本或页面访问错误。外部链接未点击，原站点的 addEventListener 集合无法枚举；监听器测试与 onclick/属性/原节点身份检查并不等价于验证所有站点交互。这里验证的是复用原生译文的浏览器回填，不包含本轮 Firefox/wllama 或 WebGPU 模型推理、整站翻译覆盖率、像素布局及速度测试。
