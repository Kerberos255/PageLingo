## 保留的修改与实测

普通内容槽要求非空；链接和强调文字要求含字母或数字。仅冠词槽允许为空。生成 grammar 限制连续空白，末尾标记后直接结束，避免完成内容后继续生成空白。解码器另保守拒绝独立否定词丢失、近似标记残片，遇到失败保留整段原文。《1984》和 `[1]` 等正常标题和引用保持有效；独立 and 可译为顿号，or 可译为斜线，不允许互换两者。

三种实验均对底座、v0.2.2、12-step 探针各运行 26 条，合计 **234 次真实 CPU 生成**。同一实验内逐条实际 prompt、grammar、预算校验一致；跨实验有意改变 grammar 或 prompt。

| 实验 | base 正常 EOS | v0.2.2 正常 EOS | 12-step 正常 EOS | 处理 |
| --- | --- | --- | --- | --- |
| 内容非空，空白仍无界 | 25/26 | 24/26 | 24/26 | 不保留 |
| 内容非空，限制空白，帧后结束 | 26/26 | 26/26 | 26/26 | 保留 |
| 上述约束再加 before/after 提示 | 26/26 | 26/26 | 26/26 | 语义未解决，撤回额外提示 |

第二组实验在加入近似标记保护前，三模型分别显示 25、26、25 条译文；最终近似标记保护后均为 **25/26**。实际调用输入未变，全部 78 条的原 DOM、代码和精确恢复通过。这些数字是显示与结构检查数，不是准确率。

曾追加普通槽纯标点保护，回放同批 78 条后分别只显示 23、24、22 条。三组 `h-guide-scope` 的完整中文语义正确，把“重启之前”移到前一个普通文字槽，末槽只剩句号；该规则却误拒绝了它们。因此已撤回这项规则，并加入实际输出的正向回归测试，允许在保持链接与 DOM 的前提下作合法中文重排。失败实验记录保留，不混入最终结果。

PyThread 长段落从每组用满 326 token、未正常结束，变为 57–58 token 正常结束，但仍遗漏“创建和启动线程”。asyncio 的 before 时序仍可能反向或含糊，并出现额外反斜杠。新增一句时序提示没有解决问题，因此生产 prompt 保持原有三条规则。

## 实际 Firefox 与边界

Firefox 158.0.1、wllama 3.6.1、CPU 单线程，用原始 v0.2.2 Q5 运行五个冻结网页片段。生产推理函数、PageTranslator、CSS、静态 worker、JSPI/CPU 补丁与 CSP 参与；使用新 profile 和 Blob 加载。此部分不是扩展 OPFS 或整页启动测试。

| 片段 | 首个非空输出 | 生成总耗时 | 实际生成速度 |
| --- | --- | --- | --- |
| 交接在订阅之前 | 107.735 s | 159.067 s | 1.4820 token/s |
| cannot 续租 | 22.120 s | 48.106 s | 1.5417 token/s |
| thenable 定义 | 35.045 s | 76.382 s | 1.5243 token/s |
| HTML 标题 | 38.611 s | 85.973 s | 1.4988 token/s |
| PyThread | 112.321 s | 157.225 s | 1.2300 token/s |

本地 Blob 传输实测 6.661 s，模型加载 10.305 s。进程树 PSS 峰值 2,747,957,248 字节，合计 RSS 峰值 3,312,041,984 字节，0.25 秒采样；RSS 包含共享页重复计数。中间三条复用 135 token 的提示前缀，不能当作冷请求比较。旧日志将推理时段标为 `before`，因此只使用可靠的整体峰值，不据此解释阶段内存；新脚本已修正阶段名。

五条的节点、属性、链接、代码、样式、双语显示和精确恢复检查通过，没有水平溢出。真实输出仍把 thenable 译成“可迭代对象”，PyThread 漏掉动作；标题输出还漏出 `〈/3 〉`。最终解码器对这五条做同消息、grammar、预算的记录回放，标题改为保留原文，其余四条仍显示；回放不计为新模型生成。

另补测未修改的生产构建、普通 content 入口和真实 example.com 整页，使用真实 OPFS、runtime 消息和 WASM。仅将精确 Hub 模型 URL 的文件传输定向到已校验的本地相同模型，发布常量和推理响应未替换。网站已改为多语言页面，手动指定 en→zh-Hans 后会尝试其他非中文区块；它们不纳入英文翻译质量分数。

普通入口首次尝试因旧的 h1/p 选择器失效，在推理前中断。第二次已完成六个区块，耗时 350.6478 s，原有中文保留，所选六段节点、样式和恢复通过；末尾链接断言因没有选中独立 a 元素而失败。再次包含 a 根节点后，又实际完成六个区块，耗时 352.6196 s、模型加载 5.680 s、进程树 PSS 峰值 2,995,864,576 字节；所有所选节点、属性、样式、代码及恢复检查通过，但辅助审计函数仅查找后代链接，仍漏掉 a 根节点本身，链接断言因此没有覆盖到实际链接。这两次均不能记作整套脚本通过，失败记录保留在报告中。

随后修复审计函数，在实际 Firefox 中对冻结的该整页进行生产 PageTranslator/CSS 回放，补齐独立 a 根节点。六个区块、链接地址与点击转发、双语显示、节点、属性、样式和精确恢复均通过，无水平溢出。此次由前述已观测显示文本重建 provider HTML，**没有原始 completion 流，不能称为相同模型原始输出回放**；没有新推理、没有性能结论。中间两次回放因 provider 设置和空白匹配问题中断，最终修正后通过。所有原始运行和回放范围明确分开记录。

## 下一组候选

新增基线另完成 **48 次真实 v0.2.2 Q5 生成**：16 条成对语义检查和 32 条 FLORES 公开参考，均正常 EOS。最终解码回放显示 48/48，DOM/代码/恢复 48/48。被撤回的纯标点实验曾误拒绝 after 样例，不能将这种逐槽现象单独判为语义错误。at-most 样例出现“至少保留最多 4”，thenable 仍被译成可迭代对象；这些是明确未过项。

32 条公开参考均显示，使用 sacrebleu 2.5.1 的 chrF2 实测 **37.8764039883713**，签名 `nrefs:1|case:mixed|eff:yes|nc:6|nw:0|space:no|version:2.5.1`。这是字符参考重合指标，不能解读为准确率。原始显示回放与最终解码回放的该分数一致。16 条未进入优化器，但已用于应用调试，不能声称对整个系统完全未见。

已在主力机共享目录部署 `run-pagelingo-quality-v2.cmd` 和 23 个按 SHA-256 锁定的运行文件。首次运行因错误前置 Firefox 检查，在训练前中断。用户指定主力机只提供 GPU 后，已部署干净提交 `38d1481fdf571f2cb292b103a8763bf8985e0494`：主力机仅训练、BF16 验证和打包；CPU 合并、Q5 与 Firefox 留给云端。训练 352 条、44 个模板家族；验证 32 条、8 个不同家族。参考由助手按模板审查，诚实标记为 `assistant_audited_synthetic`，不冒充独立人工审核。同族名词变体不算独立样本。

真实底座 tokenizer 预检：最长训练 697 token、验证 445 token，prompt/padding 屏蔽，EOS 监督，目标未截断。旧训练种子、旧 26 条回归、新 16 条成对检查、32 条 FLORES 公开参考均不进入本轮优化器；验证与训练家族分离。

两候选分别从经哈希核实的主力机历史 micro-repair r32 adapter 继续训练（lr=1e-5），或从固定底座新建 r16 LoRA（lr=3e-5）；各最多 44 步。BF16 记录中历史标签为 `v022`，但本地 adapter 与 Hub 当前 adapter 的 256 个张量均不同，不能视作已发布 v0.2.2 Q5 的同权重对照。只按验证 loss 选择候选，再做三组 BF16、云端新旧 Q5 和 Firefox 实测。**这些新候选任务不计入本份训练前基线测量。**

应用完整检查通过 179 个 JavaScript 测试、类型检查、数据导出、生产依赖审计（零漏洞）、构建与扩展检查（零错误、一条既有警告）；GPU 训练包的 23 个 Python 检查通过，包括打包完整性与损坏结果拒绝。

模型仍须通过 16 条逐例语义审查、公开参考回归、BF16/Q5 差异审查及 Firefox 实测，才决定是否推送模型。脚本不会自动上传或因 loss 下降而批准发布。操作说明见[训练包文档](../../../training/mt-fixed-slots/RESEARCH_V2.md)。
