# 范围选择 v3：停止同配方微调，调整框架任务分工

v3 的主力机任务完整结束，**908/908 次生成 EOS，全部六个阶段 exit 0**。但有效范围只选对 **13/200**；27 次给出范围中，**14 次范围错误**，其中 6 次本应放弃。因此候选不发布、不量化、不进入网页写入，不继续自动安排第四轮同配方训练。

云端另用已有 Hy-MT2-1.8B Q5 与 Qwen3-4B Q5 完成 **100 次原生 CPU 生成，100/100 EOS**。Qwen 修正了 Future 控制句的异常主体，但在缺少完整范围的 16 题中全部错误放行。问题同时涉及范围任务和个别翻译能力；目前证据不支持“换更大模型即可安全回填”，也不能把全部问题归因于基模。

## 关键翻译关系

原句：

> The function will return when any future finishes by raising an exception. If no future raises an exception then it is equivalent to ALL_COMPLETED.

v3 自然提示：

> 当任何 Future 执行完毕时，函数会抛出异常。如果没有 Future 抛出异常，则相当于 ALL_COMPLETED。

异常被移到等待函数，第一句也丢失“因抛异常而结束”的条件；简短提示同样错误。云端原始 Hy-MT Q5 的两个提示也将函数写成“通过抛出异常来返回”。Qwen 的两个提示保留了 Future 抛异常、等待函数返回的关系，例如“当任何一个未来因引发异常而结束时，该函数将返回”；“未来”这一术语仍需改进。这两句不足以证明 Qwen 整体翻译质量更好。

v3 新组中八条明确写出 exception/task 的因果句，两侧输出保留了本轮重点检查的异常主体、等待返回、否定和先后关系；这不能抵消旧 Future 失败。发送者/监视器旧句的 v3 输出虽然恢复正确异常主体，却省去了明确的 sender finishes 条件，不记为完整修复。新组 `polls` 缺少领域上下文，旧 `operator`、`draining`、无宾语 `throws` 也有歧义，保留不确定性，不因不同于参考而判错。公开保存全部自然输出，不给未完成盲审的 72 句整体正确率。

## 接下来如何优化

1. **暂停这套范围字母选择的连续 SFT。** 不增加训练轮数、不按验证损失换 checkpoint，不安排新的主力机任务。当前试验失败不等于证明 Hy-MT 无法训练，重训完整底座也没有实测依据。
2. **框架继续持有 DOM 和冻结译文，收敛范围回填。** 下一步开发先处理候选生成及可验证边界：完整否定/前缀、同词出现位置、受保护 code/链接的对应关系、不能连续表达的范围。无法证实则保留原文并计未完成；不能因为单个模型选了字母就授权写入。此为后续开发方向，本轮未宣称已经实现通用语义校验。
3. **先做离线候选覆盖与拒绝诊断，再考虑专门对齐任务。** 分开统计“候选根本不含正确范围”“选错候选”“中文本身错义”。固定旧回归，加入候选数量/排列反事实与独立真实网页来源；不能只用一致性或词面重合证明正确，也不能把已研究输出重新当全新 holdout。只有在任务和审核数据可用后，才决定是否需要专门对齐训练；翻译模型优先负责自然译义。

v14 完整译文分配实验继续默认关闭，生产回填继续遵守原节点、属性、href、code 和恢复合同。本轮没有新适配器量化、Firefox/wllama 推理、候选网页写入或 WebGPU 测量；失败在范围准入层，不能用既有浏览器回归通过代替本候选质量。已有框架网页结构证据见 [v14 报告](2026-11-06-frozen-prose-gaps-v14.md)。
