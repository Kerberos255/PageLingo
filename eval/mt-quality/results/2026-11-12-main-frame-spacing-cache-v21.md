## 改动

1. 弹窗的语言检测、翻译、恢复固定发往 `frameId: 0`。实际 MDN 含独立 iframe，原广播可返回子文档的 0 或错误；现在主文档独立决定结果。页面按钮的范围是主文档，不聚合内嵌文档。图片/右键命令已有独立 frame ID 路由。
2. 在已验证的原文字槽中，消除相邻中文链接/强调边界的英文空白，保留 Latin 技术标识的可读间距，尽量把间距放在链接外。只处理中文目标、可折叠空白和紧邻的行内正文；不改内部有意词间空格。代码、NBSP、固定/未持有的间隙、图片、SVG、空节点、换行、块边界和预格式文本保持。应用前重新检查 CSS/边界；条件变动就保留原文。准备阶段不写 DOM，恢复精确。
3. Bergamot 原来只缓存输入 HTML ≤512 字符，固定字槽标记使 8 个样本中 4 个超限。新上限4096，仍按路由和完整 HTML 匹配、LRU最多1024项，另限键加输出合计2,097,152 UTF-16 code units。该上限是字符预算，不是进程内存峰值实测值。没有加入新的 MT/API 响应缓存。

- 默认小引擎仍有明确词义错误，如软件库译成“图书馆”、Properties译成“国家财产”，以及词语生硬。间距和缓存不修正词义；本轮没有再次训练或证明MT条件/否定问题已解决。
- 整页仍有保留英文的未完成根。此次没有采集每个内容进程根的错误详情，不能把全部归因于某一规则或网络；父进程console存储的空结果无此证明力。没有放宽结构合同来让计数变好看。
- 长文首次整页依然明显慢于缓存重复访问；模型/DOM处理各有耗时。视口优先调度、取消旧任务和API缓存仍待独立评测。本轮已有的改善是主文档路由、保守间距和小引擎结构化缓存。
- 本轮没有重新完成 PageLingo-MT/API全量质量评测，也没有调用微软/Google官方凭证服务。真实站点和样本有限，未做独立盲评，不能保证任意网站排版和语义。
