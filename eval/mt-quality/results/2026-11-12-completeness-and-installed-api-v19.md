## 产品问题及修复

1. OpenAI 兼容适配器此前忽略 `finish_reason`，即使 HTML 闭合也可能接受达到 token 上限的输出。现在显式非 `stop` 状态、空结束状态和模型 refusal 均拒绝；Gemini 显式非 `STOP` 同样拒绝。旧兼容服务未提供结束字段时仍可使用，这类响应的完成状态未知，不能承诺其完整。
2. 外部适配器现在在模板/结构通过后应用共享质量检查，包括内容明显过少、异常重复和目标语言异常等；代码和固定原子从文字统计中排除。
3. 增加一个保守的英译中缺谓语信号：源文有被动谓语及并列后续谓语，译文却出现“由 Latin 名称，并且……”且缺少中文谓语。实际 v18 SQLite 烟测的缺词输出现在拒绝；另用 Acme 样本及多种正确措辞验证，不要求特定参考词。Latin 名称并列、正常中文谓语和技术英文保留有反例检查。
4. 原先根节点异常被批量翻译捕获后，弹窗可能显示“已翻译 0 个段落”。现在全失败返回原因，部分成功分别给成功数和未完成数；恢复原文清除失败记录，重试重新计算。
5. 完整扩展首次发现样式节点直接插在 `<html>` 下，改变祖先直接子节点。样式改放 `<head>`，原有严格祖先检查随后通过。样式权限及模型选择保持原配置。

这些规则覆盖明确的截断和部分漏译表现。任意省略、否定或条件反转仍需独立语义评测；本轮不能宣称已解决 MT 对 `while x is valid` 的弱化，也不是通用语义正确性证明。

## 测试过程中保留的失败及修正

- 第一版受控慢请求虽成功，但祖先检查发现 `<html>` 下新增样式节点；产品样式插入位置已修复，后续 12 个场景使用修复后的同一组生产 JS。
- 第一次真实站请求未在代理期限内回填；改用自动提前等待请求的控制器，并以单次同步 MCP 调用返回结果，第二次完整链路成功。没有增加生产等待上限。
- MDN 会自行将 `div.code-example` 升级为 `mdn-code-example`，早取祖先快照会误判。诊断记录保留具体节点变化。等待网站初始化期间没有翻译请求，随后再取快照并复测，仍使用原来的严格检查。
- MDN 的平滑滚动使初版视口截图停在页首。改成即时滚动、等待两次绘制并确认目标在视口内，另保存目标元素截图。补拍使用第二次实际返回值经完整扩展回放，不计新 API 调用，标记为 recorded response replay。

受控 12 场景所在的运行随后在真实站测试阶段失败退出；每个受控场景的实际结果及已完成断言单列保留。修正站点准备和接力后，真实站新请求及补拍分别独立运行、退出码均为 0。没有把失败运行整体标成通过。
