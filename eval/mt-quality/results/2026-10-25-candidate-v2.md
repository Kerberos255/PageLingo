# v2 候选：训练、Q5 与云端 Firefox 实测

应用结构防护可提交审查；当前候选继续保持实验状态，**不替换正式模型、不上传正式权重**。它改善了数量上下界和 thenable 概念，但复杂段落仍有时序错译、动作遗漏及不自然措辞。完整逐例结果与证据哈希见[机器可读报告](2026-10-25-candidate-v2.json)。

全部数据来自真实运行。此阶段共 240 次 GPU BF16 生成、320 次原生生成（两轮新旧 Q5 各 148 次、18 次未量化 BF16 诊断、六条 grammar 探索）和十条 Firefox/WASM 推理。记录回放不计为新生成；下一轮 v2b 的 120 步训练尚未运行。此前训练前基线另有[独立报告](2026-10-25-quality-v2.md)。

## 已完成的 GPU 训练

主力机为 RTX 4070 Ti，实测显存总量 12,878,086,144 字节、内存 34,138,730,496 字节。底座固定为 `tencent/Hy-MT2-1.8B`，revision `9a341cd1b679d3efd23b46e847b01745a71ed792`。源码包为干净提交 `38d1481fdf571f2cb292b103a8763bf8985e0494`。本次实际训练使用原 v2 的 352 条训练和 32 条验证数据。

| 候选 | 步数 | 训练耗时 | 验证 loss 前→后 | CUDA peak allocated |
| --- | --- | --- | --- | --- |
| resume-v022-r32-lr1e5 | 44 | 185.096 s | 0.522786 → 0.390821 | 4,927,850,496 B |
| fresh-r16-lr3e5 | 44 | 191.362 s | 0.708760 → 0.474110 | 4,818,798,592 B |

仅按验证 loss 选择继续训练的 r32，adapter SHA-256 `36b50ca2f3813a4e75143ddb05b7374eac06e441fe05a54debe63f2d18494ab3`。GPU 任务只做训练、三组 BF16 对照和打包，未调用 Firefox 或 CPU 转换。

GPU 中历史标签 `v022` 是主力机 micro-repair adapter（`28a0bd98…`），与 Hub 当前 adapter（`3f4ae312…`）的 256 个张量均不同。因此不能把它与已发布 GGUF 的差异归因于量化。CPU 的 `v022` 才是实际发布 GGUF，SHA-256 `8f8734198ad9332db97101de3ae7216daa3b59218522c4e0beebdfb4999924cc`。

GPU 包在分块传输后重打包，但全部 14 个原始成员的 SHA-256 保持一致，含选中 adapter、冻结计划和 240 条 BF16 原始结果。Hub adapter 仅作为无损传输参考，没有参与训练初始化。

## 云端导出与原生 CPU

CPU 合并进程实测 22.133 s、子进程 RSS 峰值 4,778,778,624 B；BF16 GGUF 转换 20.949 s，Q5 量化 51.018 s。转换器的 EOS=3 问题已在派生输出修正为 120020，BOS=120000、PAD=120002 和 chat template 全部校验通过。输入底座、旧模型和 adapter 保持原样。

新 Q5 为 1,298,755,552 字节，SHA-256 `6604d1501f6ff401a4504cf67e53a32e9a9c42e64fe1446fd22256fe15403fd7`。文件名中的 `v0.3.0-rc1` 是候选标识，不表示已发布。

云端 Debian 13，EPYC 9V74、3 个可见 CPU、cgroup 配额 2 核、内存上限 8 GiB，无 GPU、无 swap；最终检查磁盘空闲 4,170,788,864 字节。模型推理使用两个线程。以下是最终 grammar 的 74 条同输入对照：

## grammar 与防护的真实效果

原有有限连续空白和帧后直接 EOS 保留。在新增不配对标记类括号防护后，原 grammar 的新候选 thenable 输出被原子保留原文。进一步允许每个槽内边缘出现有限空白，六条探索中的该残片消失。随后重新生成完整 148 条和五条 Firefox 验证；没有用旧输出回放冒充新 grammar 推理。提示文本和预算跨两轮保持一致，grammar 有意改变。

最终新候选显示 73/74，原 grammar 加括号防护时为 72/74。旧版则由 73/74 降为 72/74：Promise 长段落用满预算后保留原文，原始重复输出已记录。新候选仍全部正常 EOS。显示数是覆盖率，不是语义准确率。

括号检查在整段及受保护代码范围内判断新增的不配对 `〔〕`、`⟬⟭`、`【】`；正常跨链接括号和原文已有不完整括号保留。此前试验的普通槽纯标点检查因误拒绝合法中文重排而撤回。

额外 18 条未量化 BF16 在同一 llama.cpp、旧 grammar、相同实际提示与预算下生成，17/18 显示。thenable 同样泄漏近似标记，asyncio 时序和 PyThread 动作遗漏也仍存在。这排除了“只由 Q5 量化造成”的解释；该对照还涉及合并权重与原 GPU BF16 后端差别，不作更强归因。

32 条 FLORES 公开参考全部显示，chrF2 实测：已发布 Q5 **37.87640399**，新候选 **38.90911467**。sacrebleu 2.5.1，签名 `nrefs:1|case:mixed|eff:yes|nc:6|nw:0|space:no|version:2.5.1`。这是小样本参考重合回归信号，不是准确率或显著优于底座的证明。

## 发布判断与下一轮

结构保护适合持续回归；原生 CPU 可承担日常质量对照，Firefox/WASM 更适合作为较慢的浏览器专项任务。主力机只需 GPU，浏览器验证可在云端完成。

当前模型尚不批准替换正式版：asyncio 时序仍错或含糊，PyThread 漏掉关键动作，两个 arrivals 句还凭空缩窄为“航班”。16 条成对检查已逐条记录；不存在把关键词通过率或原文回退计作准确率的做法。

下一轮 v2b 已增加复杂代码/换行时序、完整创建/启动动作及范围约束，合计训练 480 条、验证 64 条；仅为助手编写并按模板审查的数据。真实 tokenizer 预检最长 697/445 token，prompt/padding 屏蔽、EOS 监督、无目标截断，两个候选各限制 120 步。GPU 尚未执行，检查结果不冒充训练结果。新旧训练包和输出分别保存，操作见[训练说明](../../../training/mt-fixed-slots/RESEARCH_V2.md)。

最终应用检查：183 个 JavaScript 测试、24 个 Python 检查、类型检查、生产依赖审计零漏洞、构建、扩展检查零错误/一条既有警告。没有把权重、缓存或凭证提交到 Git。
