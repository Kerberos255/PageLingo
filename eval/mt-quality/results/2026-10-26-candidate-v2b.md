# v2b 选中候选：CPU Q5 与 Firefox 实测（2026-10-26）

结论：当前 Cloud CPU 可以完成加载、生成及 Firefox/wllama 验证，内存够用；v2b fresh r16 仍有关键语义错误，**不批准上传或替换正式模型**。结构与恢复检查通过，但显示译文不能当作语义通过。扩展另修复了实际生成暴露的行内说明标签漏拦截。

## 身份与环境

- 底座 `tencent/Hy-MT2-1.8B`，权重 SHA-256 `29e9117a44c79f81857613601968ff482d8a23c2d6736a1710bba9e5ca4762e5`；GPU 冻结包 `46eefc961beea22332e831b4a3fcc9cde8e82ef8`。
- 两组各 120 步、4 epoch 已完成。r32 验证 loss 0.4160451889038086；fresh r16 为 0.3783361315727234，按该 loss 选中 r16。这不是发布选择依据。
- r16 adapter：`85546101dce5baae57f472b92e8b722f68c4c26550b396187e0b0e5d3e844b02`；私有结果包 25,212,638 bytes，`f3aee3fdc68b74be5fb5a53759d123efb49b0587b6320a9d97233088e083fd52`，14 个成员全部校验。
- 新 Q5：`748c66dee23ec95583d0c84bd49bd3e516b0d2c1d242fbf4e152ff710e0f62bb`，1,298,755,552 bytes。BOS 120000、EOS 120020、PAD 120002 与聊天模板均通过。
- 原正式 v0.2.2 Q5：`8f8734198ad9332db97101de3ae7216daa3b59218522c4e0beebdfb4999924cc`。BF16 中的 `v022` 仍是本地历史 micro-repair adapter `28a0bd…`，不是 Hub adapter；不据此归因量化差异。
- Cloud：AMD EPYC 9V74 80-Core Processor，Debian Linux，可见/亲和 3 CPU，cgroup `200000 100000`（2 核配额），8 GiB 内存，无 GPU、无 swap。原生使用 2 线程，Firefox 使用 1 线程。

## 实测数据

本轮新增 240 条 GPU BF16、148 条原生 Q5（每模型 74 条）与 5 条真实 Firefox/WASM 生成。首 token 指实际流中首个非空 token；生成速度不包含 prompt 处理。原生“就绪”使用 `--no-warmup`，文件缓存未刻意清空，不能当作完整冷启动。

|---|---:|---:|---:|---:|

CPU 合并阶段 12.424 s，子进程 RSS 峰值 4.890 GiB；GGUF 转换 15.973 s；Q5 量化 53.441 s。峰值取 Linux `wait4`，浏览器使用 0.25 s 采样的进程合计 RSS/PSS。EOS=3 的转换器元数据问题在独立派生副本修复并验证，未改底座或 adapter。

## 结构、内容与回归

- 原生新旧模型各 74/74 的 DOM、代码、精确恢复检查通过。旧解码器显示 72/74 与 73/74；新 guard 后分别 72/74 与 72/74，拒绝项保留整段原文，不记作翻译成功。
- 真实 Firefox 五例的节点、属性、代码、链接、样式、溢出、双语和精确恢复均通过。相同五条已测 WASM 输出再在真实 Firefox 用更新解码器回放，输入消息、grammar、预算不变；说明标签案例由显示错误内容变为保留原文，其余四例正常显示。回放不算新的模型生成。
- 对已观测的 16 条成对语义诊断，助手逐条审查发现新候选两条交接时序/指代失败。并非盲测准确率；这些问题已影响训练家族设计。
- `Give token to the scheduler before subscribing to updates.` 实际新 Q5 与 WASM 都显示“先 token 将 调度器 的 更新订阅。”，未表达完整交接动作。
- after 对照实际新 Q5 为“先 token 订阅更新后，再将传递给调度器。”，受保护 token 的指代关系仍不完整。
- threading 技术段落在新 Q5 与 WASM 都漏掉“创建和启动线程”的动作，虽合法显示仍不通过内容审查。
- 标题案例实际生成在后续文字槽位塞入换行 `中文：`，WASM 还追加对规则的解释。新增解码检查只拒绝源文没有的行首说明标签，保留源文原有 `Chinese:`/`Translation:` 标签，异常在任何写回之前原子拒绝。真实输出已作回归 fixture。
- 32 条固定 FLORES-200 公开参考，全部显示；chrF2：原 Q5 37.876404，新 Q5 36.925993。该小样本重叠指标不是语义准确率，不足以证明统计显著差异或通用质量。
- GPU BF16 无 grammar 回放同样保留结构，但新候选四个段落保留原文；The 冠词空槽为允许省略，不算结构错误。

浏览器范围为官方文档/技术句子的冻结片段、本地页面、与扩展相同的静态 worker 补丁与 CSP、Blob 加载。不是新候选的整站/OPFS 自动启动测试；先前 v0.2.2 的 example.com 整页验证见[上一轮报告](2026-10-25-candidate-v2.md)。

## 后续与测试边界

不增加训练步数。下一步先通过固定 `x.cmd` 对已存在的底座/r16/r32 做[验证集诊断](../../../training/mt-fixed-slots/VALIDATION_V1.md)：内容、标记、EOS 分开计算 NLL，64 条各三组真实生成，零优化器更新。本报告写入时该新 GPU 任务尚未执行，不计入上面的实测数量。

实际 tokenizer 统计：训练正文 30,571 token，标记占 17,592（57.54%）；验证正文 4,279 token，标记占 2,964（69.27%），另有 64 个 EOS。比例不是损失贡献或已证因果解释，但总 loss 不能替代语义验收。原主力机四份旧数据共 1,792 行都明确允许移动标记，不能原样混入固定节点协议；本轮 fresh r16 从原始底座开始，没有混入这些旧行，因此不将旧协议冲突当作本轮错误的已证根因。

Cloud 可用于真实 CPU 回归，但 Firefox 五例需 9.5 分钟，不适合作为每次提交的快速全量门禁；适合定时真实冒烟，快速 DOM/协议门禁另行运行。当前代码 `npm run verify` 192 个 JS 测试、类型检查、导出、依赖审计和构建通过，扩展检查零错误/一条既有警告；Python 37 项通过。新 GPU 诊断仅完成真实 tokenizer 预检：64 行、4,343 监督 token、无截断，尚未冒充 GPU 验证。

工具前置问题均留痕：缺少 `/usr/bin/time` 后改用内核统计；真实浏览器回放先修复 JSON 键顺序比较，再补齐各片段的源 URL 上下文，严格输入校验后通过。新张量数值测试首次在未安装 PyTorch 的 CI 无法导入，现按既有可选 ML 依赖策略仅在缺少库时跳过；真实 PyTorch 环境的 37 项通过，纯 stdlib 环境的 30 项通过、7 项依赖检查跳过。均非模型无法加载。云端删除了五份可重建的旧 OPFS 模型缓存及一份旧未量化派生 GGUF，共 10,081,311,840 bytes；模型源文件、adapter、Q5 和结果记录均保留。
