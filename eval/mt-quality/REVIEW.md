# 结果分析与训练目标

当前证据支持继续完善 PageLingo 的保护措施，再做使用相同协议的定向 LoRA。没有证据支持从头预训练，也没有证据证明继续使用来源未核实的旧 adapter 会有收益。

本次生产代码固定在 `8386e33a3d2d7c2d3ced6ca42a76ee9ad61c58d0`；新增内容是评测、数据与训练工具，没有替换运行中的模型或改动生产翻译策略。以下判断来自助手逐例检查，尚未经独立人工评审。

## 已确认的问题

| 样本 | 实际现象 | 含义 |
| --- | --- | --- |
| `d-html-headings-05` | v0.2.2 把链接内的 `nest headings` 译成 `。`，相关词跑到链接前；DOM、href 与恢复检查都通过 | 节点身份保持不等于链接语义保持；标点占位也应列为拒绝条件 |
| `d-html-headings-04` | v0.2.2 固定槽位输出“在嵌套 `<h1>` 元素中嵌套多个分段元素”，颠倒了原文的容纳关系；纯文本输出方向正确 | 协议与槽位对齐负担会影响含义，不能只增加普通平行句对 |
| `d-asyncio-task-04` | v0.2.2 把 `before` 移到前槽，原强调槽为空，整段被拒绝；纯文本时序表达正常 | 需训练跨节点时序表达及每槽对应关系，保持整段拒绝策略 |
| `d-mdnpromise-04` | v0.2.2 把后半句移入 thenables 链接槽，最后一槽为空而被拒绝；底座最后一槽出现 `Chinese:` 标签也被拒绝 | 两个模型都未稳定遵守槽位语义；模板/语法只能约束外壳 |
| `d-pythread-06` | 两模型均输出空首槽，之后持续空白直到上限，保留原文；纯文本均完成 | 需要受保护代码前后短语和 EOS 终止样本；仅增加输出上限不能修复空槽 |
| `d-postgres-06` | 底座把强调的 `no` 译成“或”；v0.2.2 保留“没有”但末句仍不顺，且出现重复否定风险 | 要审查完整命题，不能以某个槽包含否定词就判为正确 |

两模型的纯文本 Promise 诊断均把 thenables 混为可迭代对象。这里还存在术语与概念问题，不全是槽位协议造成的。

## 如何读探针结果

`h-parent-worker` 的“工作者”、`h-header-spelling` 的“标头”、`h-retry-limit` 的“请勿无限重试”、`h-reader-writer` 的“阅读器”触发了过窄词表，不能直接算错译。`h-guide-scope` 的“重启服务之前”移动到链接前，完整意思和链接标签仍然合理，但违背了严格的逐槽参考。报告保留探针原样和所有观测值，未按看到的模型结果改探针抬高成绩。

目前没有人工准确率、盲评胜率、BLEU/COMET 或统计显著性结论。20 条短句和定向选择的 6 个失败不足以给模型排名。

## 接下来的执行顺序

1. **结构与标签防线。** 后续生产修复应拒绝“有意义的链接/强调文字变成纯标点”，补充真实失败回归。一般性的语义错位不能靠词表可靠识别，继续保留整段原文的拒绝路径。此评测分支先固定生产行为，以便后续修复有可比较的基线。
2. **人工审核与补数。** 按原文节点逐槽审查参考译文，再审查整句含义。重点覆盖链接边界、强调否定/时序、代码前后短语、长技术段落、thenable/事务等术语。当前 52/8 种子最长仅 268/250 token，不能代表长段训练。
3. **GPU 流程探针。** 用独立输出目录跑最多 12 个 optimizer step，确认 BF16、LoRA、保存/合并/量化/停止标记链路。该模型只用于检查流程，不作为发布候选。
4. **正式定向 LoRA。** 人工审核后扩充训练与独立验证家族，从固定 Hy-MT2 原始底座开始。使用生产 prompt、槽位目标和 EOS；prompt/padding 不计算损失。原 v0.2.2 checkpoint-10 与 Hub adapter 的对应关系未核实，不自动续训。
5. **发布对照。** 同时比较底座、v0.2.2、新候选的 BF16 与 Q5_K_M，区分训练效果和量化影响。沿用当前留出与诊断集，并增加未见过的站点/模板测试；所有新增参考应先审核，再运行候选。

结构回归、受保护代码、原文恢复必须全通过；链接标签应仍对应原短语，否定、时序、主客体和数量不能反转。译文未达到要求时保留原文。完成模型质量对照后，还需在真实 Firefox + wllama 中验证整页双语布局、交互、延迟和内存。原有 Firefox 实测证明能运行，不能代替新模型的发布检查。
