# v4：完整句义、原节点改写与槽位输出配对试验

底座仍是 `tencent/Hy-MT2-1.8B`，固定 revision `9a341cd1b679d3efd23b46e847b01745a71ed792`。本轮新建 LoRA，不续训已有语义退化候选；正式模型不变。

打开原来的 `PageLingo-MT.cmd`，在它打开的 PowerShell 窗口执行 `x.cmd`。根目录继续只有这两个可见任务入口。本轮使用新的 `pagelingo-quality-v4` 任务标识，旧 v3 的 COMPLETE 不会跳过新任务；同一个 v4 任务开始或完成后仍不会自动重复训练。

## 数据与任务

32 条训练原句、8 条验证原句、8 条留出原句；模板家族为 16/4/4，同一家族不跨集合。三种任务视图不是独立样本，参考由助手编写并检查，未经过独立人工审核。

- 自然整句翻译：保留全部动作、对象、否定、条件和时序，代码原文不变。
- 带角色的固定槽翻译：给出每个槽的 plain/link/emphasis/format 角色和受保护内容的实际含义，再输出固定槽位。
- 从中文草稿改写为固定槽：保留英文完整句义，安排适合原节点顺序的中文。7 条训练记录故意提供错误草稿，目标始终为正确译文，模型须以英文为准。

展开为 103 条训练记录（32 自然、32 固定、39 草稿改写）和 24 条验证记录。留出、旧评测、旧训练及 FLORES 原句不进入本轮优化输入；代码身份、模型可见英文去重、原生产解码和已声明的动作/链接范围要求均已检查。这些检查不等于一般语义正确性证明。

真实分词预检：训练目标 4,617 token，其中内容 1,534、标记 2,980、EOS 103；最长完整序列 546 token。验证目标 1,356 token，最长 555 token；没有截断。

## 两组受控试验

两组均从原始底座新建 r16/alpha32 LoRA，学习率 2e-5，各 32 个 optimizer steps、梯度累计 8、seed 42。训练前会校验两组初始 LoRA 张量摘要相同。

1. `ce_v4`：所有目标 token 权重为 1，作为普通交叉熵对照。
2. `marker025_v4`：完整标记 token 权重为 0.25，内容和 EOS 仍为 1；横跨标记与内容边界的 token 仍算内容。prompt 和 padding 的损失及权重为 0。

每个微批按实际监督权重之和归一化，随后由 Trainer 按梯度累计规则缩放。两组固定保留末尾 checkpoint，**不根据加权验证 loss 选赢家**。报告分别记录无权重的内容/标记/EOS NLL 及真实生成；草稿改写的参考 NLL 使用干净参考草稿，不能冒充实际两步流程准确率。

## 主力机只做 GPU

流程先验证不可变文件包、底座和旧 r16 身份，再做两组真实分词/Trainer 参数预检与评测输入预检。正式训练结束后，对原始底座、旧 r16、新 CE、新 marker025 做四组 BF16 对照。

评测计划有 80 条原句，每组最多 131 次生成、四组最多 524 次。普通生产协议回归包括 32 条 FLORES；新协议和真实草稿链在 8 条新留出及 9 条已知失败上单独记录。草稿由同一组模型真实生成；若草稿截断或动态输入超长，链条记录跳过，不把它算作成功生成。BF16 阶段没有 grammar，不能直接当作 Q5/Firefox 的显示率。

输出 `evidence.zip` 和成员 SHA 清单，只打包日志/配置/实际输出，不打包权重。两个 adapter 留在输出目录。主力机无需 Firefox、GGUF 合并或 CPU 推理；所有缓存与结果留在项目盘。云端接手结构回放、人工式逐例语义评审、是否转换候选及浏览器验证，不自动上传或发布模型。

## 云端复现与状态

```bash
npm run eval:mt-semantic
node tools/mt-semantic-kit.mjs --out /path/to/new-kit
```

可执行包要求已提交且干净的源码。`--allow-dirty` 与本地 `--runtime-models` 仅供开发预检；这类包的运行模式会被拒绝，不能作为正式训练包。

当前旧模型的角色/草稿云端对照依然存在漏译、重复和错误草稿传播；该协议仅用于有界研究试验，未接入扩展默认推理。一次试验不构成发布批准；语义、格式范围和普通翻译回归都要看实际输出。

角色和代码含义来自应用原有的 DOM/opaque 快照，属于可获得的输入，未使用目标译文作运行时提示。若候选通过，还需在本地 MT 请求链路中接入并验证相同只读元数据，不能直接把权重替换到旧提示中宣称完成部署。

GPU 结果解包后，云端运行 `node tools/mt-semantic-matrix-replay.mjs --results <unpacked-evidence> --out <new-report>`。工具核对冻结输入、实际草稿来源、四组静态 token 输入、EOS 与原生产调用，并生成逐例 JSON/HTML 对照。

## 已完成候选的故障恢复

v4 新建 LoRA 的初始化凭据是 `initial_trainable_sha256`，不需要 v3 续训流程的 `initial_adapter_sha256`。工作流分别校验 v4 的训练数据、底座、配置、32 步末尾 checkpoint、冻结底座及训练前张量摘要。

如果第一组已经保存完成，云端可用 `--reuse-ce <pinned-recovery-record.json>` 导出独立恢复任务。恢复记录必须固定原始包、训练结果、初始化记录及适配器文件的字节数/SHA；训练代码、数据与 CE 配置须与原始包相同。恢复时不写入原输出目录，不重复 CE 的优化步骤；只将已校验的训练报告复制到新结果目录，保留适配器原位置，并记录每组结果的来源。第二组仍在优化开始前核对相同初始 LoRA 摘要。

恢复任务使用单独的 `pagelingo-quality-v4-recovery` 标识，继续由原 `x.cmd` 启动。证据包额外包含两组初始化记录、工作流与候选来源；复用不代表质量评测已经通过。
