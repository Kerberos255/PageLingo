# v3：修正槽位语义的 GPU 对照训练

本轮已完成两组训练与 704 次对照生成；[实际评测与发布判断](../../eval/mt-quality/results/2026-10-29-candidate-v3.md)记录局部改善和关键回归。两组均未批准发布，暂不重复运行本任务。

原来的 `PageLingo-MT.cmd` 继续用于打开环境；在它的 PowerShell 窗口执行 `x.cmd`。根目录仍只有这两个可见 CMD 入口。

本轮修正 12 类旧训练参考（96 条），把跨越受保护代码的动作、对象放回原来的文本槽。生产提示、grammar 和 DOM 结构校验保持原样，之前的 v2 数据和运行包保持可复现。

训练集共 608 条、76 类模板；其中 128 条为新增动作完整性、nonce/摘要/密钥区别、复制与移动、字节与字符、取消与提交等技术样本。新验证集 32 条、8 类模板，与训练集分离。它们是助手编写并检查的合成数据，未经过独立人工审核；同类的名词变体不算独立样本。旧的 64 条验证原句、发布集、诊断集和 FLORES 参考均未进入新训练集。

## 主力机任务

1. 校验整个包以及底座、两组旧 adapter 的 SHA-256，并完成两组分词、训练参数和评测预检。
2. 分别从已验证的 v2b r16、r32 adapter 续训。每组固定 64 个 optimizer steps，学习率均为 1e-5，基础模型仍为 tencent/Hy-MT2-1.8B。基础权重冻结，只训练 LoRA。
3. 保留每组固定末尾权重，分别与两组旧 adapter 对照，共四组。新验证集单独报告内容、marker、EOS 的 NLL；所有评测提示都逐例记录输入哈希和实际生成。
4. 四组都完成后生成 `evidence.zip` 和 `evidence-manifest.json`。这个 ZIP 只包含证据，不包含模型权重；两个新 adapter 均留在输出目录，供云端评审后选择转换对象。

不再根据总验证 loss 自动选中或丢弃某个候选，也不自动发布模型。是否改善要同时看关键动作、先后关系、角色、术语、结构校验和普通段落回归。无 grammar BF16 的可显示数不能当线上翻译准确率。

主力机流程只需要已有 GPU 和训练环境；不需要 Firefox、模型 CPU 合并或 GGUF 转换工具。所有缓存和结果仍在项目所在盘。云端接手语义评审、候选转换、Q5 和 Firefox 验证。

本轮使用独立 `pagelingo-quality-v3` 任务标识，旧任务的 COMPLETE 不会使新任务跳过。已经开始或完成的同一个 v3 任务仍不会重复启动。`x.cmd status` 只读取状态；通常无需 `retry`。

## 云端准备

先运行 `npm run eval:mt-targeted` 与 `npm run eval:mt-curriculum`，再使用 `node tools/mt-curriculum-kit.mjs --out <new-directory>` 导出不可变运行包。最终 GPU 包要求已提交且干净的源代码；`--allow-dirty` 只供开发预检，其产物不能用于训练。

已观察到的发布失败类型用于设计课程，因此后续发布结果属于回归验证，不是盲测。不要把当前验证失败原句复制进训练集来提高分数。
