# 有界范围选择训练试验

本任务是候选试验，不是发布训练。现有模型在冻结译文的闭集范围选择对照中，基础模型仅对 2/18，v0.2.2 对 3/18；大多选择放弃。两种提示下，二者还都将 Future 因抛异常结束误译为等待函数抛异常。结构合同无法纠正整句误译，也无法仅靠对齐分数证明完整概念。

从固定版本 `tencent/Hy-MT2-1.8B` 原始 BF16 基础模型初始化新的 r16 LoRA，最多 **128 个 optimizer steps**，不续接旧适配器。基础权重 SHA、revision、优化参数见 [config-scope-choice-v1.json](config-scope-choice-v1.json)。旧模型、适配器和缓存保留。

## 数据与判断

- 训练 712 条：544 条冻结译文范围选择，168 条自然翻译复习；验证 100 条，独立合成 holdout 100 条。数据由 [scope_choice_data.py](scope_choice_data.py) 确定性生成，均明确标为助手审查的合成数据，未声称独立人工审查。
- 范围选择包含前缀/反向概念、同词不同出现、部分词片段、吞入其他动作和无连续范围时放弃。正确项随候选排列变化。只能输出候选字母或 X，不能改写冻结译文。
- 训练、验证、holdout 的词组对和模板族分开；holdout 不参与优化或 checkpoint 选择。自然翻译包含新的动作参与者、异常来源及时间条件对照。既有真实网页和 26 条冷对照请求仅用于评测，不导入优化器。
- batch=1、梯度累计=8，使用每个序列的平均目标交叉熵，避免长翻译目标按 token 数淹没短字母/EOS 任务；提示及 padding 不计损失，EOS 受监督，不截断目标。
- 固定选择第 128 步最终 checkpoint，验证损失不自动决定胜者。基础模型和候选各做 126 次 BF16 生成：100 条 holdout 与 26 条已有诊断请求。约束字母格式不等于选对范围；自然译文需要审查语义，不能用是否与单个参考逐字相等裁决。

## 启动包

云端构建工具为 `python tools/mt-scope-training-package.py --out <新目录> --cold-controls <已冻结的 selector-control-plan.json>`。工具只打包脚本、数据、评测计划和哈希，不含权重。最终包应绑定已提交源码且 `source_dirty=false`；未提交预检包不能当作最终任务发放。

解压到主力机原 `E:\PageLingo-MT`，保留已有 `PageLingo-MT.cmd`。打开它，然后只执行 **`x.cmd`**。包中唯一根目录 CMD 为 x.cmd，稳定启动器通过 `tools/mt-control/current-task.json` 指向不可变任务包。

主力机只执行 GPU 预检、基础模型 BF16 对照、LoRA 训练、候选 BF16 对照和结果打包。不安装依赖，不要求 Firefox，不做 CPU 转换，不上传模型。所有缓存/临时目录由启动器绑定原项目盘；从 C 盘或 UNC 路径直接启动会拒绝。需要原项目 Python 环境及支持 BF16 的 CUDA GPU。

`x.cmd status` 只读状态；`x.cmd check` 预检但不优化，输出目录与正式 run 分开。相同已完成任务不会自动重训。失败保留阶段日志，修复后使用 `x.cmd retry`。`workflow_completed` 仅在实际训练和两侧评测完成、结果包 CRC 校验通过后成立；单独 check 的完成状态不占用正式 run。

运行结果为 `outputs/scope-choice-v1-run-*/gpu-handoff.zip`，包含 LoRA 与 BF16 原始输出、配置和日志，不含基础权重/缓存/训练中间 checkpoint。云端核验后接手量化、CPU 和 Firefox 测试。

## 继续推进的门槛

先检查两次候选排列是否稳定选中完整范围、放弃是否正确，以及自然翻译是否保持动作主体、否定、条件和因果关系。现有 dereferencing、重复 level 和异常返回失败样本必须保留。再检查量化结果与真实网页的原节点、链接、代码、格式范围、监听器及还原。

此包完成只代表拿到候选证据；不自动切换默认模型，不自动开启实验回填，不上传权重或合并 PR。小合成集的提高不能证明整站泛化或消除所有语义错误；若只记住字母、过度放弃或损害自然翻译，应拒绝候选并根据实际输出调整下一轮。
