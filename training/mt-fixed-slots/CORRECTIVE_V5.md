# v5：完整固定槽、动作对象和时序纠正对照

v4 草稿改写未通过质量门槛。v5 只训练完整固定槽输出，不训练自然草稿或草稿改写；不修改扩展默认推理。参考为助手编写并检查的合成数据，未独立人工审核，只用于小规模研究试验。

## 两组只比较提示

两组加载固定 Hy-MT2-1.8B 底座和同一个旧 r16 adapter，不续训被拒绝的 v3/v4 新候选。初始 adapter 权重 SHA 为 `85546101dce5baae57f472b92e8b722f68c4c26550b396187e0b0e5d3e844b02`。第一组优化前记录 LoRA 张量摘要，第二组优化前核对完全相同；底座冻结。

- `legacy_v5` 使用当前生产固定槽提示。
- `roles_v5` 使用 v4 冻结的节点角色和实际代码只读上下文提示。该提示仍只存在于研究代码，尚未接入扩展默认链路。

两组 64 条训练原句、目标槽位、顺序、seed、r16/alpha32、学习率 1e-5、batch 1、梯度累计 8、普通 causal CE 和 32 个 optimizer steps 相同。64 条样本运行 4 轮，固定保留末尾权重。标记/内容/EOS 使用普通交叉熵，prompt/padding 屏蔽；不按验证 loss 自动选赢家。对照只比较此预算下两种提示的表现，不是数据、初始化和提示各因素的完整消融。

## 数据

64 条训练、8 条验证、8 条新留出；16/4/4 个不相交家族。四类内容各占训练 16 条：代码末尾之前的多动作、明确的早于/晚于、链接/强调内的完整动作或术语、传递已绑定方法/函数引用的参与者与禁止操作。每句有完整槽位参考、代码身份检查和声明的动作/范围要求。

旧训练/评测、v4 全部原句及当前留出不进入新优化输入，还检查移除代码名称后的实际输入去重。导出必须经生产固定槽解码，运行时核对两组源句 ID、目标和顺序相同；这些检查不等于一般语义等价证明。新留出继续只作评测。

## 主力机

打开原 `PageLingo-MT.cmd`，再运行唯一任务入口 `x.cmd`。`pagelingo-quality-v5` 标识避免旧 COMPLETE 跳过新任务；运行中/完成后不会自动重复。现有两个可见 CMD 内容不用改动。

流程先做实际分词、Trainer 参数与评测预检，再分别训练两组 32 步，最后比较底座、旧 r16、legacy_v5、roles_v5。96 条原句，每组最多 146 次、四组最多 584 次生成：96 次旧协议、25 次角色提示、25 次自然整句诊断；没有草稿改写。自然诊断不参与本轮优化。BF16 阶段没有 grammar，不能当成 Q5/Firefox 显示率。

验证的无权重内容/标记/EOS NLL 按 legacy/roles 提示分别记录，和实际输出分开。主力机只需要 GPU，不需要 Firefox、CPU 转换、下载新底座或上传权重。缓存和结果留在项目盘。完成后输出 `evidence.zip`、成员 SHA、模型身份、两组训练/初始化记录；适配器留在主力机。

云端负责实际输出的冻结输入核对、生产渲染/代码/恢复回放和逐例语义检查。只有格式覆盖、动作/对象/时序、链接/强调范围和普通翻译回归同时通过，才考虑量化与浏览器验证。

## 云端准备

```bash
npm run eval:mt-semantic
npm run eval:mt-corrective
node tools/mt-corrective-kit.mjs --out /path/to/new-kit
```

运行包必须来自干净、已提交的源码；`--allow-dirty` / `--runtime-models` 只供开发预检，正式 run 会拒绝。GPU 结果导入后，用 `tools/mt-semantic-matrix-replay.mjs` 按结果包内的 v5 profile 回放；模型标签与历史 v4 严格区分。
